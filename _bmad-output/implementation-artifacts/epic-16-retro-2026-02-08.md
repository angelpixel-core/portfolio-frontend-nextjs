## What Went Well

### 1. Mock-First Development
- Sistema de auth completo sin dependencia de backend Rails
- `mockLogin`, `mockSignup`, `mockLogout`, `mockOAuthLogin` con delays realistas (800-1200ms)
- Velocidad de desarrollo máxima sin bloqueos por servicios externos

### 2. Type Consolidation (Story 16.1)
- `AuthUser` consolidado como fuente canónica en `services/auth/types.ts`
- Hooks semánticos: `useAuth`, `useUser`, `useIsAuthenticated`
- Eliminó duplicación y estableció API limpia para todo el epic

### 3. Adversarial Code Reviews
- Encontraron bugs reales en cada story
- Story 16.4: triggerRef click-outside fix (dropdown se reabría)
- Story 16.5: runtime validation en `loadSession` (structure + TTL)
- Story 16.3: `performOAuthLogin` via service interface (no direct mock import)

### 4. Testing Coverage Incremental
- Cada story agregó tests (no testing sprint al final)
- Total: 126 unit tests + 27 E2E tests auth-specific
- E2E Critical Flows table actualizada en CLAUDE.md

### 5. Provider-Agnostic Architecture
- `OAuthService` interface con `MockOAuthService` implementation
- Swap a backend real es plug-and-play
- Feature flag: `NEXT_PUBLIC_OAUTH_ENABLED`

### 6. Accessibility (WCAG 2.1 AA)

## Key Patterns Discovered

### Barrel Import Contamination (3/7 stories)
- `@/atoms/icons/index.js` barrel con 58+ re-exports
- Cualquier import desde barrel arrastra ~50 KiB al chunk
- Afectó: OAuthButtons (16.2), SocialAuthDropdown (16.3), AuthButton (16.4)
- **Pattern establecido:** Siempre usar direct path imports
- **Documentado:** MEMORY.md

### Jest Mock Hoisting (6/7 stories)
- `jest.mock()` calls se hoistean ARRIBA de variable declarations
- Helper functions referenciadas en factories fallan
- **Fix:** Inline factory functions directamente en `jest.mock()`
- **Documentado:** MEMORY.md

### SSR Hydration Race Condition
- `getInitialAuthState()` evalúa en module-import time
- En SSR, `loadSession()` retorna null (no hay `window`)
- AuthProvider `useEffect` con `isAuthenticated=false` limpia localStorage
- **Fix E2E:** `addInitScript` para inyectar session antes de page load

### Dual Elements in Responsive DOM
- A 1280px viewport, dos AuthButtons renderizados (mobile-auth + ui-zone)
- `getByTestId` sin scope resuelve 2 elementos → strict mode violation
- **Fix:** Scope selectors al zone correcto (`header-ui-zone`)

## Architecture Decisions (Epic 16)

### State Management Split
```
UI State (Redux): authPanel (isOpen, isAuthenticated, user, error)
Server State (React Query): domains (articles, projects, etc.)
```

### Provider Tree Order
```
ReduxProvider → AuthProvider → ReactQueryProvider → ThemeProvider → TransitionProvider
```

### Service Layer Pattern
```
Component → Service (performOAuthLogin, performLogout)
         → Dispatch Redux action (loginSuccess, logout)
         → AuthProvider detects change → localStorage sync
```

### Session Persistence
- Key: `auth_session` en localStorage
- TTL: 7 días (604,800,000 ms)
- Cross-tab sync via StorageEvent
- Hydration: `getInitialAuthState()` en Redux slice initialState

## Key Learnings (para referencia futura)

1. **Mock-first + scope mínimo** funciona extremadamente bien para desacoplar equipos
2. **Definir qué NO es la épica** es tan importante como definir qué sí
3. **Auth ≠ user management** — esta distinción evitó scope creep
4. **Tests E2E deben evolucionar con la UI**, no bloquearla
5. **Provider-agnostic desde el día 1** evita refactors caros
6. **Code reviews adversariales** encuentran bugs reales — no son rubber-stamp
