## What Could Improve

### 1. Verificacion de Datos es el Cuello de Botella
- 47 findings en 7 stories, mayoria por metricas incorrectas
- Conteos off-by-one, selectores CSS inexistentes, asunciones no verificadas
- El review los atrapa pero consume esfuerzo significativo
- **Root cause:** Auditorias iniciales son aproximadas; el review force precision

### 2. Follow-Through de Retro: 25%
- Baja de 50% (Epic 19) a 25% (Epic 20)
- DOC-1 (retro Epic 18) prometida en 2 retros consecutivas y no hecha
- **Root cause:** Demasiados action items (10 en Epic 19). El sistema no absorbe esa cantidad.
- **Solucion:** Maximo 3 action items por retro, priorizados implacablemente.

### 3. Epic Status No Se Actualiza al Cerrar
- `epic-20: in-progress` pese a 7/7 stories done
- Mismo problema flaggeado en Epic 19 retro
- **Root cause:** No hay step automatico o habito de cerrar epic status

## Key Patterns Discovered

### Verificacion Triple es Necesaria (7/7 stories)
- Cada story revelo datos incorrectos en auditorias iniciales
- Solo la combinacion de auditoria + documento + code review produce datos confiables
- Pattern: grep/find counts → documento → review adversarial → correccion

### Documentation-Only Epics Tienen su Propio Tipo de Complejidad
- No tocan codigo pero requieren precision de datos extrema
- El code review encuentra errores diferentes (metricas, no bugs)
- La calidad del documento depende de la calidad de la auditoria

### Every Layout Naming Value (Story 20.6)
- El valor de primitivos de layout no es solo CSS — es vocabulario compartido
- Nombrar comportamientos (Stack, Center, Cluster) mejora comunicacion
- Adoptar los 7 primitivos aunque CSS equivalente ya exista en Tailwind
