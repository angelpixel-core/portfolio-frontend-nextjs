## What Could Improve

### 1. Sprint-Status Desincronizado
- Epic 19 no registrado en sprint-status.yaml
- Epic 18 sigue como `in-progress` aunque 3/3 stories done
- Perdida de visibilidad y trazabilidad del avance
- **Root cause:** No hay step obligatorio de actualizar sprint-status al cerrar epic

### 2. Retro de Epic 18 Perdida
- No existe documento de retro para Epic 18 (Bundle Performance)
- Lecciones de LazyMotion, dynamic imports, y m-refactor no persistidas
- Rompe continuidad historica de aprendizaje
- **Root cause:** Se salto de Epic 18 a 19 sin retro

### 3. --legacy-peer-deps Sin Formalizar
- Requerido en CADA operacion npm (ci, install, uninstall)
- Documentado informalmente en CLAUDE.md pero no en backlog como deuda
- Riesgo latente: oculta conflictos reales de dependencias
- **Root cause:** Deuda conocida pero no tracked formalmente

### 4. Next.js API Gotchas Silenciosas
- `author` ignorado (debe ser `authors: [{name}]`) — Story 19.5
- `keywords` como string funciona pero formato canonico es array — Story 19.5
- `new Error()` shadow del constructor nativo — Story 19.1
- Next.js no emite warning para metadata incorrecta
- **Root cause:** Framework acepta input invalido sin feedback

### 5. Estructura de Artefactos No Normalizada
- Retros en `implementation-artifacts/`, epics en `planning-artifacts/epics/` y en `epics/`
- Analisis sueltos en `analysis/`
- No hay convencion clara para busqueda y documentacion historica
- **Root cause:** Crecimiento organico sin definir estructura desde el inicio

## Key Patterns Discovered

### Consistencia del Code Review (6/6 stories)
- Cada story tuvo exactamente ~5 findings (2-3 MEDIUM + 2-3 LOW)
- 0 HIGH en todo el epic
- Evidencia de calidad base consistente
- Code review agrega valor real, no es rubber-stamp

### Cross-Platform Assumptions (19.2)
- macOS case-insensitive oculta bugs de import paths
- `Skeleton` vs `skeleton` pasa local, falla en Docker/Linux
- Bug preexistente de Story 14-11 nunca detectado sin Docker build
- **Leccion:** CI en Linux o check de case-sensitivity previene estos bugs

### Next.js Metadata API Pitfalls (19.1, 19.4, 19.5)
- Framework acepta metadata incorrecta silenciosamente
- Solo el code review adversarial detecto los problemas
- **Leccion:** Checklist de metadata o linting rule customizado

### Atomic Commits + Adversarial Review (6/6 stories)
- Patron replicable: implementacion → atomic commits → review → fix → atomic commits
- Separacion clara entre codigo de feature y fixes de review
- Trazabilidad completa en git history

## Breakthrough Moments

1. **Docker Multi-Stage** (19.2) — De ~900MB single-stage a 177MB con Alpine, non-root, healthcheck. Template reusable para cualquier Next.js project.

2. **CSP Centralization** (19.3) — Mover headers de vercel.json a next.config.js permitio testing local y conditional unsafe-eval para dev.

3. **Case-Sensitivity Discovery** (19.2) — Bug fantasma desde Story 14-11 descubierto al hacer Docker build en Alpine. Demuestra valor de builds cross-platform.

4. **OG Image Optimization** (19.4) — Reduccion de 34KB a 18KB cambiando de 16-bit RGBA a 8-bit RGB. Detalle fino de code review.

5. **devtools in Production Deps** (19.6) — react-query-devtools tenia lazy import + NODE_ENV guard, asi que nunca llegaba al bundle. Pero estaba en production deps — riesgo latente descubierto por review.

4. **Deuda tecnica no tracked se normaliza** — --legacy-peer-deps lleva meses sin formalizarse
5. **Cross-platform builds descubren bugs invisibles** — case-sensitivity solo falla en Linux/Docker
6. **Next.js acepta metadata incorrecta silenciosamente** — solo el review humano/adversarial lo detecta
