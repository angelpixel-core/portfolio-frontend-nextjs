## What We Learned

### 1. Épicas Híbridas
**Qué pasó:** Epic 14 mezcló UX, refactor y bug fixing. Funcionó en resultados, pero generó confusión de foco durante el sprint.

**Principio establecido:**
> Las épicas híbridas están permitidas solo cuando el refactor desbloquea UX o estabilidad. Deben declararse como híbridas desde el kickoff.

### 2. Tests Legacy
**Qué pasó:** Había 33-45 tests fallando antes de la épica. Durante el sprint generaron ruido y dudas. Se decidió no arreglarlos dentro del scope.

**Principio establecido:**
> "Un test que no refleja la UI o el comportamiento actual es deuda, no protección."

**Decisión correcta:**
- Cerrar la épica con tests pasando
- Postergar la auditoría profunda de testing a otra fase

### 3. Detección de Bugs
**Qué pasó:** El menú mobile no se cerraba al navegar. Se detectó tarde, pero se arregló rápido.

**Aprendizaje:** El problema no fue el fix, fue la detección. Necesitamos E2E tests para flujos críticos.

### 4. Foto Final Post-Épica
**Qué pasó:** Se cerró Epic 14 con éxito, pero faltaba visión global inmediata del estado del codebase.

**Principio establecido:**
> Después de cada épica grande: mini-auditoría de estado (code quality, tests, performance). No para ejecutar todo, sino para decidir prioridades.

### 5. Scope & Closure
**Qué salió bien:**
- Se resistió la tentación del "ya que estamos..."
- Se cerró la épica aun sabiendo que había cosas mejorables

**Regla de oro reafirmada:**
> "Cerrar bien es más valioso que pulir infinito."
