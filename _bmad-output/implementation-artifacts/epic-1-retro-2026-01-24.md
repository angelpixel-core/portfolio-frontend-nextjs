## Challenges and Growth Areas

### Core Insight

> **"Epic 1 no fallo por falta de calidad, sino por falta de limites explicitos sobre que deuda se corrige cuando."**

The team:
- Detected debt ✅
- Documented it ✅
- But had no clear agreement on WHEN to pay it ✅/❌

**This is a process problem, not an execution problem.**

### Specific Challenges

| Challenge | Stories Affected | Root Cause |
|-----------|------------------|------------|
| Pre-existing test failures carried forward | 1.1, 1.2, 1.7, 1.8 | No escalation trigger |
| framer-motion mock patterns repeated | 1.6, 1.7, 1.8 | No shared test utility |
| Partial icon aria-hidden coverage | 1.7, 1.8 | "Good enough" without explicit scope |
| Jest cache issues on JS->TS migration | 1.3, 1.4, 1.5 | Learned pattern mid-epic |

### Friction Categories Identified

1. **Knowledge gaps** - Debugging tools, catching issues
   - Solution: Document, learn, then fix

2. **Dependency drift** - URLs deprecate, versions unlock
   - Solution: Lockfiles, periodic audits

3. **Silent failures** - Animations, side effects that don't break build
   - Solution: Visual regression or E2E coverage

## Key Insights and Learnings

### Quote of the Retrospective

> "Avanzamos rapido porque aceptamos deuda, pero no la encapsulamos."

### Patterns Elevated to Project Standards

These are no longer "discoveries" - they are mandatory practices:

| Pattern | Description | Source Story |
|---------|-------------|--------------|
| Delete JS before TS | Delete .js file BEFORE creating .ts to avoid Jest cache | 1.3 |
| useReducedMotion | Wrapper hook for framer-motion accessibility | 1.8 |
| jest-axe baseline | Not optional "extra" - required for components | 1.7 |
| TDD pragmatico | RED -> GREEN -> atomic commit | All stories |

### What We'd Do Differently

1. Establish debt escalation rule from day 1
2. Create shared test utilities earlier (framer-motion mocks)
3. Timebox legacy fixes rather than deferring indefinitely

## New Rules and Agreements

### Rule 1: Technical Debt Escalation (2-Story Rule)

```
If debt appears in 2+ stories,
it stops being "documented debt" and becomes "mandatory technical story".
```

**Application:**
- No more "we'll get to it"
- No more carrying forward indefinitely
- Explicit decision: fix now OR freeze with documented rationale

### Rule 2: Epic Gate - Sanitation Story

Before starting any new epic, evaluate if a sanitation story is needed based on:
- Debt carryover from previous epic
- 2-story rule violations
- Known blockers for upcoming work
